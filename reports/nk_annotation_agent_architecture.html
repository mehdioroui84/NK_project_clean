Optional annotation refinement agent

Architecture of the NK refined-label agent

The agent is designed as a controlled, reviewable refinement layer: it gathers evidence, proposes a pipeline-safe label, performs targeted pairwise refinement when needed, and exports files that can be reviewed before script 04 applies labels.

Pipeline location: 03b → reviewed CSV → 04
Input evidence
LLM decision loop
Pairwise refinement
Safety / review rails
Exported outputs

Why this structure?

The agent is kept evidence-first and file-based, so every decision can be audited. Nothing moves into training until the reviewed mapping CSV is accepted.

How novelty is handled

Possible new biology is recorded as an alternative suggestion, not automatically promoted to a training label. Strong novelty needs coherent markers, pairwise support, and low technical concern.

Where it connects

The approved mapping feeds scripts/04_apply_refined_v1_labels.py, then the existing SCANVI training, evaluation, and attribution pipeline can run normally.
